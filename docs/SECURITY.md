# Security boundaries

The control UI trusts the configured Fluxer instance and Jellyfin server. All viewers share the dedicated non-admin Jellyfin user's library permissions. Fluxer community membership permits browsing; current voice presence is required for every playback mutation. Metadata may remain cached for up to ten seconds after a Jellyfin permission change; playback sources are resolved directly.

OAuth authorization codes use PKCE and state bound to an HTTP-only signed flow cookie. The cookie contains a random nonce, expiry, and MAC, with no user credentials or PKCE verifier. Server-derived PKCE/state values use separate HMAC purposes. Unauthenticated sign-in starts allocate no pending-flow entries; verified callbacks are replay-protected with bounded, expiring state. Restarting invalidates flow cookies and sessions.

Admission limits apply before network requests. Configure trusted proxy CIDRs carefully: Uvicorn's automatic proxy-header rewriting is disabled, and only the application can accept a forwarded client address from a configured peer. A successful sign-in does not remove per-user request limits. Global concurrency, bounded caches, body limits, and per-user SSE limits protect upstream capacity. Distributed network floods still require edge protection.

The Linux media entry point installs Landlock and seccomp before importing native media libraries. The backend is non-dumpable. Workers cannot read arbitrary application files or backend `/proc` credentials, signal other processes, execute child programs, or open Unix-domain connections. The container smoke test demonstrates these denials alongside real PyAV decoding and LiveKit source initialization. This is defense in depth, not protection against all kernel/native-library vulnerabilities. The worker retains the source credentials and voice grant necessary to publish, and outbound IP networking remains available. Docker/Kubernetes resource bounds contain memory and temporary storage usage. No privileged container or extra capabilities are required. Linux hosts without the required confinement support fail closed; macOS development is outside this guarantee.

## Node2Shell and React2Shell

- **Node2Shell (CVE-2026-111497)** is a native Brotli decoding bug. It also affects consumers outside Node.js. The official Node fixes include 22.23.4, 24.22.1, and 26.12.1. The image uses a patched Node builder and does not copy Node into the runtime. HTTPX has no optional Brotli decoder in the pinned runtime, explicitly does not advertise Brotli, and rejects Brotli response headers before reading or decoding the body. Compressed inbound request bodies are rejected. If a Debian Brotli library is present, the image check requires the distro's fixed version. Native media libraries remain a separate attack surface and should stay updated. [Node advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases), [Brotli fix](https://github.com/google/brotli/releases/tag/v1.2.1), [Debian status](https://security-tracker.debian.org/tracker/CVE-2026-111497).
- **React2Shell (CVE-2025-55182)** concerns React Server Components. This app uses browser-only React, with no Next.js, server actions, or `react-server-dom-*` packages. [React advisory](https://react.dev/blog/2025/12/03/critical-security-vulnerability-in-react-server-components).

Dependency advisory scans are useful but do not certify the complete service or every bundled native library. Dependabot updates produce PRs; deployments must still be updated by the operator. Live Fluxer/Jellyfin compatibility and long-duration synchronization validation remain pending.
